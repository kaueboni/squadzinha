squadzinha

Uma squad de subagentes do Claude Code para spec-driven development, com o Opus como advisor. Os agentes trabalham, o Opus aconselha nos pontos difíceis, e você aprova só o que importa.

sonnet · trabalha haiku · lê opus · aconselha você · aprova

1. A squad

Seis subagentes instalados em .claude/agents/ do projeto. Cada um só pode tocar no que o papel exige.

haiku · só leitura

discovery

Mapeia o projeto como ele é hoje: arquivos, padrões, integrações lidas e escritas.

haiku · web

researcher

Confere na documentação oficial o que o discovery marcou como "a confirmar".

sonnet · escreve specs

tech-lead

Escreve a spec da feature e o plano de tarefas. Nunca implementa. Pede revisão de riscos ao Opus antes de entregar.

sonnet · testes

contract-tester

Escreve testes de contrato das integrações antes do código, a partir da spec.

sonnet · código

developer

Implementa uma tarefa com TDD. Mesmo erro 2x → consulta o Opus.

sonnet · não edita

auditor

Roda testes e lint, confere o diff e devolve APROVADO ou REPROVADO.

Os modelos vêm de model_read (haiku) e model_work (sonnet) no .claude/minimal-squad.json.

2. O fluxo de uma feature

você
/spec <feature>
discovery → researcher

Como o projeto é hoje e o que a documentação confirma.

tech-lead + opus revisa

Escreve specs/NNN-SPEC-<feature>.md.

⏸ você aprova a spec
você
/build auto NNN
tech-lead + opus revisa

Gera tasks/plan.md e tasks/todo.md.

⏸ você aprova o plano (única aprovação do build)
para cada tarefa

ciclo a–e (abaixo), um commit por tarefa

auditor no conjunto

Revisa a feature inteira, atualiza o PROGRESS.md e lista as suposições decididas com o Opus.

você

/review, testes de integração, push e deploy. Agentes nunca fazem isso.

3. O ciclo de uma tarefa

a · contract-tester (se "Integração: sim")

Escreve os testes de contrato, confirma que falham e guarda o hash de cada arquivo.

b · developer

RED → GREEN → testes e lint. Não mexe em testes de contrato. Mesmo erro 2x → Opus.

c · auditor

Diff, testes, hashes dos contratos, checklist de segurança e escopo.

e · APROVADO

Marca a tarefa no todo.md e faz commit só dos arquivos dela.

d · REPROVADO

Volta ao developer com os itens críticos. Até 2 rodadas.

3ª reprovação · opus

Recebe os três pareceres e o diff e devolve a causa raiz. O developer faz uma última rodada.

reprovou de novo → para e mostra o parecer + diagnóstico

Sem o advisor, a squad já pararia na 3ª reprovação.

4. O que o advisor faz

O advisor é um recurso do Claude Code: o modelo que está trabalhando pode consultar um modelo mais forte. O Opus lê a sessão inteira (todas as chamadas e resultados) e devolve um conselho. Ele não edita arquivos e não aprova nada: quem aplica é o agente, e quem decide se a squad para é o texto do /build.

Mesmo erro 2x—developer consulta antes da 3ª tentativa
Spec e plano—tech-lead pede riscos e lacunas antes de entregar

O Opus pode resolver

  • causa raiz de reprovação repetida
  • interpretação de spec ambígua (fica registrada)
  • revisão de riscos da spec e do plano
  • erro que se repete no developer

Só você decide

  • aprovar a spec e o plano
  • mudar um teste de contrato
  • "Ask first": schema, contrato, dependência, credencial, infraestrutura
  • o que git revert não desfaz: escrita externa, dados, deploy

5. Guardrails

Spec de base fixa

SPEC.md descreve o projeto; agentes nunca escrevem nele e o pre-commit bloqueia.

Pre-commit

Busca de segredos, lint e testes em todo commit.

Contratos travados

O hash dos testes de contrato é conferido pelo auditor; mudou = reprovado.

Integração é humana

Testes @pytest.mark.integration nunca rodam por agente; fixtures são sempre fictícias.

6. Instalar

Uma vez por máquina:

/plugin marketplace add kaueboni/squadzinha
/plugin install minimal-squad@squadzinha

Uma vez por projeto (repositório git, sem mudanças pendentes):

/minimal-squad:init

O init detecta testes, lint e specs, mostra tudo e espera sua confirmação. Depois cria a branch chore/minimal-squad com um commit por etapa, e nada é publicado. Reinicie o Claude Code no fim.

7. Configuração

.claude/minimal-squad.json, os campos que mais importam:

{
  "params": {
    "test_cmd": "pytest -q",
    "lint_cmd": "ruff check .",
    "model_read": "haiku",
    "model_work": "sonnet",
    "advisor": "opus"          // vazio desliga
  },
  "overrides": {
    "agents": {
      "developer": { "skills_extra": ["nova-tool-ag-ui"] },
      "auditor":   { "skills_extra": ["testar-poc"] }
    }
  }
}

advisor vira advisorModel no .claude/settings.json, sem sobrescrever um valor seu, e os subagentes herdam. Skills do projeto ficam em .claude/skills/ e entram por skills_extra. Veja o exemplo em examples/poc-ag-ui-strands/.
